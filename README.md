# TCP Chat

[![CodeFactor](https://www.codefactor.io/repository/github/mysticslippers/tcp-chat/badge)](https://www.codefactor.io/repository/github/mysticslippers/tcp-chat)

Учебный чат на Go с TCP-сервером и полноэкранным терминальным клиентом на Bubble Tea. В проекте можно проследить путь сообщения от ввода в терминале до рассылки участникам комнаты и сохранения истории.

- Общение в комнатах, уникальные ники и личные сообщения между комнатами.
- Уведомления о переходах между комнатами и восстановление истории после перезапуска сервера.
- Автодополнение команд, прокрутка ленты, счётчик новых сообщений и автоматическое переподключение.

## Запуск

Нужен Go 1.27 или новее. Команды выполняются из корня проекта. Для клиента откройте вкладку Terminal в IDE или отдельный терминал.

1. Запустите сервер в первом терминале.

   ```sh
   go run -buildvcs=false ./cmd/server
   ```

2. Запустите клиент во втором терминале. Для проверки чата откройте ещё один клиент в третьем.

   ```sh
   go run -buildvcs=false ./cmd/client
   ```

Сервер и клиент используют `localhost:9000`. Новый клиент получает ник вида `guest-1` и попадает в комнату `general`. Флаг `-buildvcs=false` отключает добавление сведений из Git в сборку.

Чтобы проверить комнаты, задайте клиентам ники через `/nick alex` и `/nick bob`, затем выполните `/join games` в обоих. Обычная строка появится у участников `games`. Команда `/msg bob Привет!` из клиента `alex` отправит личное сообщение.

Для выхода из клиента используйте `/quit` или Ctrl+C. Чтобы штатно остановить сервер, введите `exit` в его консоли или нажмите Ctrl+C.

## Команды

| Команда | Действие |
| --- | --- |
| `/help` | Показать справку по командам сервера |
| `/nick <имя>` | Установить уникальный ник |
| `/rooms` | Показать комнаты и число участников в каждой |
| `/join <комната>` | Перейти в комнату и создать её при необходимости |
| `/where` | Показать текущую комнату |
| `/who` | Показать участников текущей комнаты |
| `/online` | Показать общее число подключённых клиентов |
| `/msg <ник> <текст>` | Отправить личное сообщение |
| `/history` | Показать последние публичные сообщения текущей комнаты |
| `/stats` | Показать число публичных сообщений, отправленных за текущую сессию |
| `/quit` | Закрыть клиент |

Начните вводить команду и нажмите Tab, чтобы принять подсказку. Стрелки вверх и вниз переключают варианты. PgUp и PgDn прокручивают ленту. Если читать старые сообщения, клиент считает новые события, пришедшие от сервера. End возвращает в конец ленты и сбрасывает счётчик.

## История и переподключение

Сервер хранит до 20 последних публичных сообщений на комнату. Он сохраняет комнаты и историю в `history.json` в своей рабочей папке раз в секунду и при штатном завершении. При следующем запуске сервер читает этот файл.

При обрыве связи клиент сохраняет ленту и черновик и пробует подключиться снова. После неудачной попытки он ждёт две секунды. Новое подключение создаёт сессию с гостевым ником в `general`, и сервер снова отправляет историю этой комнаты.

## Как устроен проект

- [`cmd/server`](cmd/server) — запуск TCP-сервера, автосохранение и завершение работы.
- [`internal/server`](internal/server) — сессии, комнаты, история и рассылка. Хаб защищает общее состояние мьютексом. У каждого клиента своя очередь исходящих сообщений и горутина записи в сокет.
- [`internal/server/commands`](internal/server/commands) — обработчики команд чата.
- [`cmd/client`](cmd/client) — сетевые операции и интерфейс Bubble Tea. Ответы сервера поступают в модель как события, которые обновляют ленту.

Клиент отправляет текстовые строки с `\n` в конце. Сервер отправляет ответы как JSON-строки. Такой ответ может содержать несколько строк, например справку или историю.

## Сборка и тесты

```sh
go build -buildvcs=false ./...
go test -buildvcs=false ./...
```

Тесты проверяют уникальность и повторное использование ников, конкурентное переименование, лимит истории и возврат её копии, порядок сообщений в очереди и тайм-аут записи.
